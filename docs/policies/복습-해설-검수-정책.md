## 복습(재풀이) 정책 — #151

정본 코드: `server/.../quiz/QuizService.java`의 `getStepQuiz`/`validateAccessible`, `app/src/features/history/review-params.ts`

- **완료한 스텝의 문제를 슬롯 지정으로 다시 조회**하는 API(`GET /quizzes/steps/{stepOrder}/{slotOrder}`)는 시도 이력을 전혀 보지 않는다 — 항상 그 슬롯의 문제를 그대로 반환한다. "이미 다 시도한 스텝"이라 `/next`의 "미시도만" 로직이 안 맞아서 별도로 만든 API.
- **접근 제어**: 현재 진행 스텝 **이하**(현재 스텝 포함)만 허용, 그보다 미래인 스텝은 `QUIZ_NOT_ACCESSIBLE`(403). `courseId`는 클라이언트가 보내지 않고 서버가 `stepOrder`로부터 직접 역산 — 위조 불가.
- ⚠️ 이 접근 검증은 "완료된 스텝"과 "진행 중인 현재 스텝"을 구분하지 않는다 — `getStepQuiz`만 놓고 보면 현재 진행 중인 스텝도 재조회 가능하다. 히스토리 **목록** 화면(`getCompletedSteps`)이 `currentStepOrder - 1`까지만 보여줘서 실질적으로 "완료한 것만" 노출될 뿐, API 자체의 제약은 아니다.
- **재풀이 흐름 상태는 서버에 없다** — 전부 URL 쿼리파라미터로 클라이언트가 들고 다닌다(`step`/`slot`/`rc`/`rs`/`topic`/`single`). 전체 복습(슬롯 1→5 순차) vs 문제 번호 하나만 골라 풀기(`single=1`, 풀면 바로 완료 화면) 두 모드가 있다.
- 복습 중 정답 제출은 **일반 채점 경로와 완전히 동일**(새 `QuizAttempt` 생성, `validateAccessible` 재사용) — 다만 복습의 정답 수·연속 정답(`rc`/`rs`)은 URL로만 이어지고, 오늘의 학습 스트릭이나 보리 포만감에는 전혀 영향을 주지 않는다(의도된 분리).

## 콘텐츠 검수(저작 승인) 정책

**정본은 이 문서가 아니라 `quiz-authoring` 스킬이다** — 슬롯 구성·검증 규칙(`[[키워드]]` 마커, 빈칸 규칙, 코드 지문 판정 등)이 매우 상세하고 빠르게 바뀌므로 여기서 복붙하지 않는다(과거에 복붙했다가 코드와 갈라진 전례 있음, `content-rules.md` 자체에 기록됨).

- 검증 규칙 전체 → `.claude/skills/quiz-authoring/references/content-rules.md`
- 대시보드 승인 플로우(검수→승인→라이브 반영, 되돌리기 불가) → `.claude/skills/quiz-authoring/references/dashboard.md`
- 브리지/실행 인프라 → `.claude/skills/quiz-authoring/references/bridge.md`

핵심만 요약: **승인은 즉시 라이브 반영이며 되돌리는 API가 없다.** IMPROVE 승인은 원본을 파괴적으로 덮어쓴다. 검증(`GeneratedQuizValidator`)을 하나라도 어기면 스텝 전체가 저장되지 않는다(부분 저장 없음) — 사람의 의미 검수는 이 자동 검증과 별개로 여전히 필요하다(코드 지문 가드는 "보수적인 가드"일 뿐 컴파일러가 아님).
