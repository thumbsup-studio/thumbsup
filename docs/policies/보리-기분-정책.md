## 확정된 정책 (#35, 구현됨)

포만감(fullness)은 배치·스케줄러 없이 **조회 시점마다 파생 계산**한다. 저장하는 건 "마지막으로 먹인 시점"과 "그때의 포만감"뿐이고, 현재값은 그로부터 경과일수만큼 감소시켜 즉시 계산한다.

- **초기값**: 신규 유저 50%(보통 상태) — `Mascot.INITIAL_FULLNESS = 50`
- **먹이 지급량**: 세션(퀴즈 5문제) 완료마다 **고정 +20%** — `Mascot.FEED_AMOUNT = 20`. 정답 수 비례 아님, 완료 자체로 지급.
- **시간 경과 감소**: 하루 **-10%** — `Mascot.DECAY_PER_DAY = 10`. 배치 없이 `getCurrentFullness(now)`가 마지막 먹이 시점부터 경과일 × 10을 빼서 즉시 계산.
- **범위 캡**: 0~100% 사이로 clamp. 100% 초과분은 버려짐(리셋·레벨업 트리거 없음), 0% 밑으로도 안 내려감.
- **레벨**: 코드에 레벨업 로직 없음 — "Lv.1 아기 강아지" 고정 표기(포만감 누적과 무관).
- **표정 3단계** (`home-logic.getCharacterMood`, 10% 단위 경계):
  | 포만감 | 표정 |
  |---|---|
  | 70% 이상 | 행복(happy) |
  | 30~69% | 보통(neutral) |
  | 29% 이하 | 배고픔(hungry) |
- **동시성**: 첫 먹이 요청 시 행이 없으면 생성 — 유니크 제약 위반 시 재조회로 레이스 해소(`QuizService.lockOrCreateProgress`와 동일 패턴).
- **API**: `GET /api/v1/mascot`(이름·현재 포만감 조회, 행 없으면 기본값만 반환·생성 안 함), `POST /api/v1/mascot/feed`(세션 완료 시 프론트가 호출).
- **학습 개념 수**: 히스토리 그래프(#10 Atlas)의 "배운 노드 수"와 같은 이벤트(`QuizStepCompletedEvent`)를 구독해 계산 — 화면 간 수치가 항상 일치한다(#233 `LearnedConceptRecorder`).

코드: `server/src/main/java/studio/thumbsup/server/mascot/Mascot.java`, `MascotService.java` · `app/src/features/home/home-logic.ts`, `api.ts`

## 아직 정해지지 않은 것

### #57(감정 고도화)의 전제가 이미 부분적으로 해소됨 — 재검토 필요
#57은 "#35는 먹이만 주는 단순판이고, 방치 시 시무룩해지는 감소 로직은 #57에서 분리 구현한다"는 전제로 쓰였다. **하지만 시간 경과 감소(하루 -10%)는 이미 #35 구현에 포함되어 있다.** 즉 "방치하면 포만감이 떨어져 배고픔(hungry) 상태로 전환되고, 다시 학습하면 먹이로 회복된다"는 기능은 사실상 이미 동작한다.

#57이 실제로 더 필요로 하는 것은:
- "배고픔(hungry)"과 별개로 더 극단적인 "시무룩" 표정/상태가 필요한지, 아니면 hungry로 충분한지
- "복귀" 자체(단순 홈 진입)를 별도 트리거로 인정할지, 아니면 먹이(세션 완료)를 통해서만 회복되는 현재 방식으로 충분한지
- 오답만 풀어도(참여 자체로) 감정이 회복되는지 — 현재는 세션 "완료"가 기준이라 정답률과 무관하게 이미 이 조건을 만족함

**결론**: #57 착수 전에 "이미 구현된 것과 다른 부분이 정말 있는지"부터 재확인 권장. 없다면 #57은 닫고 표정 3단계(happy/neutral/hungry)를 최종 정책으로 채택하면 됨.
