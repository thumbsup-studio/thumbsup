# 스트릭·폭죽(팡파레) 기준

> 관련 이슈: #68(연속 정답 빵빠레, 완료 — 이후 동작 변경됨) · #171(단계별 연출 고도화, 완료 — 이후 동작 변경됨) · #211/#262(팡파레 발동 조건 변경, 이 문서가 반영하는 최신 상태) · #189(이 문서의 출처)
> 최종 확인: 2026-08-03

## ⚠️ 먼저 — 용어 3개를 구분해야 한다

이슈 텍스트(#68·#171 등)에서 "연속 정답"이라는 말이 서로 다른 세 가지를 가리키는 데 섞여 쓰여서 혼동을 일으킨다. 실제 코드에는 완전히 분리된 세 메커니즘이 있다:

| 용어 | 정의 | 저장 위치 | 초기화 시점 |
|---|---|---|---|
| **일별 스트릭** | 하루에 스텝을 하나라도 완료했는지(요일 단위) | 서버 `UserProgress.streak` | 하루라도 건너뛰면 리셋 |
| **콤보** | 한 세션 안에서 문제를 연속으로 맞힌 횟수 | 클라이언트 `session-progress.ts`(휘발성) | 오답 1번에 리셋 |
| **완주 팡파레** | 스텝(5문제) 전체를 다 맞혔는지(퍼펙트 여부) | 클라이언트 `sessionStorage`(재생 여부만, 1회성) | 세션당 1회 판정 |

아래는 이 셋을 각각 설명한다.

## 1. 일별 스트릭 (서버, `UserProgress`)

- "오늘 스텝을 하나라도 완료"했는지가 기준 — 문제 정답 수와 무관.
- 같은 날 여러 번 완료해도 **하루 1회만 반영**(멱등) — `today.equals(lastCompletedDate)`면 아무 것도 안 함.
- 어제 완료 → 오늘 완료면 `streak + 1`, 어제가 아니면(하루 이상 건너뜀) `streak = 1`로 리셋.
- 날짜 기준은 KST. 조회 시점에 "끊긴 상태"를 다시 계산(`getEffectiveStreak`)하고 DB에 끊긴 값을 미리 써두지 않는다.
- 동시 요청 레이스는 유저·코스 단위 행 잠금(pessimistic lock)으로 직렬화.

이 스트릭은 **연속 정답/콤보/팡파레와 완전히 무관**하다 — 오답을 아무리 많이 내도 스텝만 완료하면 오른다.

## 2. 콤보 (클라이언트, per-question) — #211/#262에서 재설계됨

`app/src/features/play/celebration-logic.ts`. **답을 낼 때마다** 3단계 중 하나로 즉시 피드백:

| 콤보 | 단계 | 연출 |
|---|---|---|
| 1 | subtle | 칭찬 문구만, 별도 표시 없음 |
| 2 | combo | "N콤보" 칩 표시 |
| 3 이상 | confetti | 컨페티 1회 발사 |

- **3 이상은 전부 같은 단계다** — 콤보 3이든 100이든 연출·문구 풀·`holdMs` 전부 동일, 더 커지지 않는다(상한선 없음이 아니라 "3에서 고정").
- 오답이면 무조건 `tier: "none"`(콤보 즉시 0으로 리셋).
- 배지(`badge`) 오버레이: 재도전 성공 시 "다시 잡았어요"(우선), 아니면 HARD 난이도 정답 시 "난이도 상 정복" — 배지가 있으면 최소 `combo` 단계로 끌어올림(subtle 단계에 배지만 덜렁 안 붙게).
- `prefers-reduced-motion`이면 실제 단계와 무관하게 **표시만** subtle로 강제 다운그레이드(문구·배지 텍스트는 유지, 칩 pop·컨페티 같은 시각효과만 제거), `holdMs`도 0(자동 홀드 없이 탭하면 바로 넘어감).
- 같은 문제는 항상 같은 칭찬 문구(quizId 기반 결정적 선택) — 새로고침해도 문구가 안 바뀜.

## 3. 완주 팡파레 (Lottie 오버레이) — #68/#171 원안에서 크게 바뀜

**⚠️ #171 이슈 원문의 "3/4/5연속 정답 단계별 연출"은 더 이상 사실이 아니다.** `insight-page.tsx`에 남은 코드 주석이 명시:

> "팡파레는 이제 '연속 3정답'이 아니라 완주 퍼펙트에만 터진다(이슈 211). 3콤보는 퀴즈 화면에서 이미 컨페티로 축하했으므로 여기서 또 터뜨리면 중복이다."

현재(2026-08-03) 정책:
- 발동 조건: **스텝(또는 복습 세션) 전체를 만점으로 완주**했을 때만(`correct >= totalCount`), 그 스텝의 **마지막 문제 해설에서 1회**.
- 3/4/5단계 구분 **없음** — 항상 같은 Lottie(`FANFARE_SOURCES`, 두 애니메이션 동시 재생) 1종.
- `sessionStorage`로 `playKey`(예: `daily:{quizId}`, `review:{step}`)별 1회만 재생 — 새로고침·뒤로가기로 재마운트해도 중복 재생 안 함.
- 문제 번호 하나만 고르는 단건 복습(`single=1`)에서는 발동 안 함(분모가 1이라 항상 "만점"이 되어버려 의미 없음).
- `prefers-reduced-motion`이면 오버레이 자체를 아예 렌더링 안 함(축소版이 아니라 완전 생략).
- Lottie의 `complete` 이벤트로 자연 종료 — 콤보 시스템(2번)과는 화면·트리거가 겹치지 않아 발생 시점이 충돌할 일이 없다(콤보=문제마다, 팡파레=스텝 마지막에 한 번).

## 정리 — 이슈 히스토리 반영 상태

- #68(최초 구현): 연속 3정답부터 팡파레. → 이후 폐기.
- #171(단계별 고도화): 3/4/5연속 구분 시도. → 이후 폐기.
- #211/#262(현재): 팡파레는 "완주 퍼펙트"로 좁히고, 문제별 즉시 피드백은 콤보 시스템(1/2/3+ 3단계)이 전담 — 두 화면(S3 퀴즈/S4 해설)에서 같은 걸 두 번 축하하던 중복을 없앰.

**앞으로 #68·#171을 다시 열 일이 있다면**, "3/4/5연속" 스펙으로 되돌리는 게 아니라 이 위 정리된 3계층 구조를 기준으로 논의할 것.
