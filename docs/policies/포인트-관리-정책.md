# 포인트 관리 정책

> 관련 이슈: #24(포인트 표시·내역·프리즈, 미구현) · #189(이 문서의 출처)
> 최종 확인: 2026-08-03

## 확정된 사실 — 포인트는 실제로 구현되어 있지 않다

이슈 텍스트 곳곳(#19, #63, #35 등)에 "정답당 +10P"라는 표현이 반복되지만, **서버에 실제 포인트 적립 로직은 없다.**

- `UserProgress` 엔티티에 `points` 필드가 존재하고 `/api/v1/home` 응답에도 `points`가 내려가지만, **생성 시 항상 0으로 초기화될 뿐 어디에서도 증가시키는 코드가 없다.** (`UserProgressService.recordStepCompletion`이 유저 최초 생성 시 `UserProgress.create(userId, 0, 0)`으로 만들 뿐)
- 앱 화면의 "+10P" 배지(`verdict-banner.tsx`)는 **정답이면 항상 뜨는 하드코딩된 텍스트**다. 난이도·재도전·콤보와 무관하게 무조건 표시되고, 실제 API 응답 필드와 연결되어 있지 않다. 서버의 `points` 값을 읽지도, 갱신을 트리거하지도 않는다.
- 홈 화면 UI에도 `points`를 표시할 자리가 없다(`app/src/features/home/api.ts` 주석: "points는 현재 홈 UI에 표시 자리가 없어 매핑하지 않는다").

**즉 "+10P"는 순수 장식용 문구이고, 포인트 이코노미는 아직 설계·구현 어느 쪽도 시작되지 않았다.**

## #24가 실제로 필요로 하는 것 (전부 미정)

#24(포인트 내역·프리즈 표시/구매)는 현재 "준비중" mock으로만 존재한다(서버 API 자체가 없음). 실구현하려면 아래가 먼저 팀 결정이 필요하다:

- **적립원**: 어떤 행동에 몇 점을 주는가(정답당? 세션 완료당? 스트릭 유지당?) — 화면상 "+10P" 문구를 실제 규칙으로 삼을지부터 결정 필요
- **차감/소모**: 스트릭 프리즈 구매 가격, 그 외 소모처
- **프리즈 재화 정책**: 보유 상한, 획득/구매 방식, 실제 사용 시 스트릭(#51/`UserProgress.streak`) 로직과의 연동 방식
- **내역 API**: 적립/소모 이벤트를 어떻게 로그로 남길지(현재 `/api/v1` 어디에도 포인트 내역 엔드포인트 없음)
- **홈-프로필 값 일치**: 프로필에 실시간 잔액을 보여준다면 홈과 동일 소스(`UserProgress.points`)를 써야 함(현재 홈은 아예 표시 안 함)

## 권장 순서

1. "+10P" 배지를 실제 규칙에 맞게 고치거나(적립원 결정 후), 정책 확정 전까지는 정직하게 제거/보류하는 편이 오해를 줄인다.
2. 포인트를 실제로 쌓이게 하려면 `UserProgress.points`를 증가시키는 코드부터 필요(현재 필드만 있고 미사용).
3. #24의 "내역·프리즈"는 그 이후 — 적립원이 없으면 내역 화면도 지어낼 데이터가 없다.
