# 퀴즈 구성·채점 정책

> 관련 이슈: #19(세션 구성, 완료) · #42(채점 API, 완료) · #63(재도전, 완료) · #189(이 문서의 출처)
> 최종 확인: 2026-08-03

## 세션 구성 (#19)

**스텝당 5문제, 슬롯 1~5, 하2·중2·상1 고정 — 콘텐츠 저작 파이프라인이 강제하는 구조라 사실상 불변이다.**

| 슬롯 | 유형 | 난이도(형식) |
|---|---|---|
| 1 | OX | EASY |
| 2 | OX | EASY |
| 3 | MULTIPLE_CHOICE | MEDIUM |
| 4 | MULTIPLE_CHOICE | MEDIUM |
| 5 | KEYWORD_BLANK | HARD |

- 이 조합은 문제 **저작 시점**에 `GeneratedQuizValidator.EXPECTED_SLOTS`로 강제된다 — 어긋나면 생성 자체가 실패해 저장되지 않는다(`quiz-authoring` 스킬의 `content-rules.md` 참조, 정본은 그쪽 — 여기서 중복 설명하지 않는다).
- ⚠️ 이 표의 난이도는 "문제 **유형**의 형식 난이도"다. "얼마나 쉬운/어려운 개념을 다루는가"(콘텐츠 난이도)는 별도 축(`GenerationLevel`)이고, 저작 파이프라인은 현재 이 축을 안 쓴다(STANDARD 고정) — 혼동 주의.
- 런타임 코드(`QuizService`)는 slotOrder↔difficulty 결합을 **강제하지 않는다** — 저작 단계 검증 + 관례로만 보장됨. `RetryHintBuilder`가 이를 명시적으로 인지하고 있다("현재 데이터에서 OX는 항상 EASY지만 코드가 그 결합을 가정하지 않는다").
- 오답이어도 램프는 그대로 상승한다 — 재출제·난이도 하향 없이 선형 진행.

### 미정 사항
- 세션 중단·복귀 정책(이어하기 vs 리셋) — 홈 재진입·딥링크 재진입 시 재개/신규 여부
- 세션 내 뒤로가기(이전 문제로 되돌아가 답 변경) 허용 여부
- 난이도별 재고 부족(예: 상 문제 없음) 시 처리 방식 — 현재는 콘텐츠가 항상 5슬롯 꽉 채워진다는 전제로 동작, 부족 시나리오 미검증

## 채점 규칙 (#42)

정본 코드: `server/src/main/java/studio/thumbsup/server/quiz/QuizService.java` (`grade*` 메서드군)

- **OX**: 제출값 1개를 `Quiz.correctAnswer`("O"/"X")와 대소문자 무시 비교.
- **MULTIPLE_CHOICE**: 제출값을 `choiceId`(Long)로 파싱 → 해당 선택지의 `isCorrect` 여부 반환. 파싱 실패·존재하지 않는 id는 자동 오답.
- **KEYWORD_BLANK**: 슬롯별로 등록된 동의어 중 **하나라도 일치하면 정답**. 비교 전 정규화 — **모든 공백 제거**(전각 공백 U+3000 포함) + 대소문자 무시. 예: "시스템 콜"과 "시스템콜"은 같은 답으로 처리. 제출 개수가 등록된 **고유 슬롯 수**와 다르면 즉시 오답.
- 모든 제출은 `QuizAttempt`로 매번 새로 쌓인다(재도전 포함, dedup 없음).

## 오답 재도전 정책 (#63)

정본 코드: `server/src/main/java/studio/thumbsup/server/quiz/RetryHintBuilder.java`

**재도전 힌트 발급 조건 — 셋 다 만족해야 함**: 오답 && 난이도가 MEDIUM 또는 HARD && 유형이 OX가 아님. (EASY는 항상 제외, OX는 유형으로 한 번 더 방어 — 현재 데이터상 EASY=OX라 사실상 같은 조건이지만 코드는 둘 다 명시적으로 체크한다.)

- **사지선다**: 오답 선택지 중 정확히 **1개를 소거**(`eliminatedChoiceId`) — 이번에 고른 오답은 다시 못 지운다(정보성이 없어서), 남은 오답 중 `displayOrder`가 가장 낮은 것을 소거.
- **키워드 빈칸**: 슬롯별로 **첫 글자 + 공백 제외 글자수**를 공개(`revealedPrefix`, `answerLength`) — 동의어가 여럿이면 가장 먼저 등록된(id가 가장 낮은) 것 기준.
- **서버는 "재도전 소진" 상태를 저장하지 않는다.** 몇 번을 다시 제출해도 서버는 매번 새로 채점하고 조건이 맞으면 매번 새 힌트를 계산해 돌려준다 — "1회만" 제한은 **전적으로 클라이언트(`play-page.tsx`의 `hasUsedRetry` 상태)가 강제**한다.
- 재도전 성공/실패와 무관하게 **채점·스텝 진행·지급 로직은 첫 시도와 완전히 동일**하다(차등 없음).

### 미정 사항
- 재도전이 세션 진행 카운트(n/5)에 영향을 주는지 — 현재는 같은 문제 번호를 유지(새 문제로 카운트 안 됨)로 동작하지만 팀 확정 문서는 없음
- 재도전 성공이 콤보(연속 정답, `스트릭-폭죽-기준.md` 참조)에 포함되는지 — 현재 코드는 포함시킨다(정상 정답과 동일 취급), 의도된 것인지 재확인 필요
- 재도전 대기 중 건너뛰기·북마크 등 다른 기능과의 상호작용(해당 기능 자체가 아직 없어 실질적으로 발생 안 함)
