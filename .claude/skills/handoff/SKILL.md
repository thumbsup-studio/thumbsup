# 작업 인계 (Handoff)

개발을 비롯한 모든 업무는 체이닝돼 있다. 내 작업이 끝나면 **다음 작업자에게 맥락·지시사항·가이드라인을 넘겨야 한다.** 이 스킬은 그 전달물의 형식과 내용을 강제한다.

## 핵심 원칙

**상세함과 장황함은 다르다.** 상세함은 다음 사람이 필요로 하는 정보를 빠짐없이 주는 것이다. 장황함은 (a) 같은 정보를 두 곳에 반복하거나 (b) 다음 사람이 몰라도 되는 것을 늘어놓는 것이다. 장황한 것은 모두가 싫어한다. AI도 그렇다.

**주제넘지 않는다.** 다음 사람이 판단해서 결정해야 할 사항을 미리 결정하지 않는다. Fact 위주로 정보만 전달하고, 미해결 질문은 질문인 채로 남긴다.

---

## 전달물은 두 층으로 나눈다

### 1층 — 정본 (GitHub 이슈 코멘트 / 문서)

**여기에 전부 쓴다. 길어도 된다.**

다음 사람도 AI를 써서 작업한다. AI는 사람보다 훨씬 많은 양을 빠르게 읽고 정확히 참고한다. 그러니 전달하고 싶은 바를 디테일하게 담아 긴 문서를 줘도 좋다 — 그게 장황한 게 아니다.

**반드시 넣을 것**

- **무엇이 바뀌었나 / 무엇이 생겼나** — 계약, 스키마, 타입, 엔드포인트. 복사해서 쓸 수 있는 형태로.
- **기획 의도** — 왜 이 기능이 존재하는지의 핵심 개요. 다음 사람의 판단에 필요한 만큼만.
- **바뀐 것이 어느 코드와 맞닿나** — 관련 파일·함수를 *출발점으로* 짚는다. 단 (1) 실제 코드를 읽고 짚는다(짐작 금지), (2) 확신 없으면 단정하지 말고 "아마 이 근처(파일)"로 남긴다, (3) **어떻게 고칠지는 그 사람이 결정한다 — 나는 "위치"라는 사실만 준다.** 내가 읽지 않은 상대 영역은 파일을 짚는 대신 계약/인터페이스만 주고 통합 지점은 그쪽에 맡긴다.
- **주의사항** — 빠지기 쉬운 함정, 지키지 않으면 깨지는 불변식.
- **경계 — 없는 것 / 안 정해진 것 / 내 소관 밖** — 다음 사람(과 그의 AI)은 빈칸을 실제 있는 것처럼 채우려 든다. 그러니 *없다는 사실*을 못박는다. 예: "서버 응답에 `xxx` 필드 아직 없음(#NN)", "라우팅 대상 미정(#NN) — 임의로 만들지 말 것", "정렬은 이번 범위 밖". 경계를 안 그으면 다음 사람이 유령 위에 코드를 쌓다 헛돈다.
- **AI 작업 프롬프트** — 복붙해서 바로 쓸 수 있는 지시서. `<details>`로 접어 넣는다.

**반드시 뺄 것**

- 내가 그 기술을 선택한 **이유**, 검토했던 **대안**, 뒤집었던 **의사결정 과정**
- 내가 겪은 삽질, 리뷰에서 고친 것, 성능 실측치
- 다음 사람이 몰라도 되는 내부 구현 디테일

> 이런 건 PR 본문이나 커밋 메시지에 남긴다. 인계문에 넣으면 신호가 묻히고 오히려 혼동을 준다.

### 2층 — 메신저 (슬랙 / 카카오톡)

**정말 간단하게. 3~6줄.** 결국 사람이 작업을 시작해야 하므로 알림은 필요하다. 하지만 메신저의 유일한 목적은 **정본으로 유도하는 것**이다.

- 무슨 일이 있었는지 **한 줄**
- 그 사람이 **해야 할 일**을 한 줄씩 (요청 형태로)
- **링크**
- **멘션** — 받는 사람을 지목한다. 지목 없는 공지는 아무도 자기 일로 안 받는다.

**어차피 링크를 열면 알게 될 정보를 여기에 다시 쓰지 않는다.** 스키마, 코드 예제, 필드 목록, 주의사항 전부 금지. 읽는 사람에게 피로감만 준다.

```text
(자세한 사항은 GitHub 이슈에 정리해뒀으니 확인 부탁드립니다)
```
이 한 줄이면 충분하다.

## 수신자별로 나눈다

**여러 사람·여러 이슈를 뭉뚱그리지 않는다.** 뭉뚱그리면 "그래서 내가 뭘 해야 하지?"가 남지 않는다.

- 이슈가 둘이면 항목을 둘로 나눈다.
- 사람이 둘이면 메시지를 둘로 나눈다.
- "공유합니다"가 아니라 **"추가 작업 요청드립니다"** — 요청인지 참고인지 분명히 한다.

---

## 작성 절차

1. **다음 작업자를 특정한다.** GitHub assignee, 관련 이슈, 진행 중인 브랜치를 확인한다.
   ```bash
   gh issue list --repo <owner>/<repo> --state open --json number,title,assignees,labels
   git for-each-ref --sort=-committerdate --format='%(committerdate:short) %(refname:short)' refs/remotes/origin | head
   ```
2. **그 사람이 이미 짜놓은 코드를 읽는다.** 브랜치가 있으면 실제 구현을 본다. 무엇이 바뀌어야 하는지 파일·함수 단위로 짚기 위해서다. 짐작으로 쓰지 않는다.
3. **정본을 쓴다** — 위 "반드시 넣을 것" 기준으로. AI 작업 프롬프트를 포함한다.
4. **이슈 코멘트 초안을 쓴다.** 멘션을 맨 앞에 둔다(assignee 구독 알림만으로는 약하다). **게시 전 사용자에게 확인받는다 — 이슈 코멘트도 외부로 공개되는 액션이다.**
5. **메신저 문구를 쓴다** — 3~6줄. 정본에 있는 내용을 반복하지 않는다.
6. **외부로 나가는 것은 확인받고 내보낸다.** 이슈 코멘트 게시·메신저 발송 등 외부 공개 액션은 사용자 확인 없이 하지 않는다.

## 템플릿

### 이슈 코멘트

````markdown
@<받는사람>

## <무엇이 생겼나> (PR #NN)

<다음 사람의 현재 코드를 읽고, 무엇이 바뀌는지 한두 문단>

### 계약 / 타입
<복사해서 쓸 수 있는 형태>

### 지금 코드에서 바꿔야 할 것
<파일명·함수명 단위로>

### 주의사항
1. ...

### 아직 없는 것 (이번 범위 밖)
- <필드/기능> — #NN

<details>
<summary>AI 작업 프롬프트 (복붙용)</summary>

```
<배경 3~5줄>
<계약/타입>
## 할 일
1. ...
## 규칙
- <레포 규약, 로드할 스킬, 완료 게이트>
## 하지 말 것
- 아직 없는 것을 임의로 만들어내지 않는다
```

</details>
````

### 메신저

```text
@<받는사람> <무엇이 생겼는지 한 줄> (PR #NN). 추가 작업 요청드려요
1) <할 일 A> (#NN) <링크>
2) <할 일 B> (#NN) <링크>
상세는 각 이슈 코멘트에 정리해뒀어요
```

## AI 작업 프롬프트에 담을 것

다음 사람이 AI에게 그대로 붙여넣을 지시서다. 원래부터 있었던 커뮤니케이션이지, AI를 위한 특별한 산출물이 아니다.

- **배경** — 무엇이 준비됐는지, 어디를 호출하면 되는지
- **계약** — 타입·스키마·불변식. "서버가 보장하니 방어 코드 불필요" 같은 문장이 여기 들어간다
- **할 일** — 번호 매긴 목록. 파일 경로를 적는다
- **규칙** — 레포 규약, 먼저 로드할 스킬, 통과해야 할 게이트
- **하지 말 것** — 특히 *"아직 없는 것을 임의로 지어내지 말 것"*. AI는 빈칸을 채우려 든다

**빼야 할 것**: 내가 왜 이렇게 설계했는지. 대안 비교. 성능 수치.

## 자기 점검

인계문을 보내기 전에 확인한다.

- [ ] 메신저 문구에 정본과 **중복되는 정보**가 있는가? → 지운다
- [ ] 내 **의사결정 과정**이 인계문에 들어갔는가? → 지운다 (PR 본문으로)
- [ ] 다음 사람이 **결정해야 할 것을 내가 결정**했는가? → 질문으로 되돌린다
- [ ] 여러 이슈·여러 사람을 **뭉뚱그렸는가**? → 나눈다
- [ ] **멘션**이 있는가?
- [ ] 다음 사람의 **실제 코드를 읽고** 썼는가, 짐작으로 썼는가?
- [ ] **내 범위 밖**이 무엇인지 명시했는가?
- [ ] 메신저 문구가 **6줄 이내**인가?

## 안티패턴

**메신저에 스키마를 복붙한다**
→ 링크를 열면 볼 내용이다. 한 줄 요약 + 링크로 끝낸다.

**"#12랑 #8 확인해주세요"**
→ 뭉뚱그렸다. 각 이슈에 무엇을 해야 하는지 한 줄씩 나눈다.

**멘션 없이 채널에 던진다**
→ 아무도 자기 일로 받지 않는다.

**"이 방식을 고른 이유는 A/B/C를 비교했을 때…"**
→ 다음 사람에게 불필요하다. 그가 알아야 할 건 "무엇을 어떻게 쓰는가"다.

**"이건 이렇게 하시면 될 것 같아요"** (그쪽 소관인데 미리 정함)
→ Fact와 선택지만 준다. 결정은 그 사람 몫이다.

**브랜치를 안 읽고 일반론을 쓴다**
→ "정규식 매칭 코드는 지우시면 됩니다"처럼 **그 사람 파일을 짚어야** 실제로 움직인다.
