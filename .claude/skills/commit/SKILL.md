# 커밋 컨벤션 (Thumbs Up)

## 커밋 전 체크 (순서대로)

1. **현재 브랜치 확인** — `git branch --show-current`
   - `main`이면 **커밋 금지**. 먼저 브랜치 생성: `<type>/<이슈번호>-<짧은-슬러그>`
     - 예: `feat/12-like-button`, `fix/23-login-crash`, `chore/33-nextjs-setup`
   - 이슈 번호를 모르면 사용자에게 묻는다. 이슈가 없는 작업이면 이슈부터 만들지 제안.
2. **스테이징** — 이번 작업과 관련된 파일만 `git add`. 관련 없는 변경이 섞여 있으면 분리해서 별도 커밋.
3. **메시지 작성** — 아래 형식.

## 메시지 형식

```
<type>(<scope>): <요약> (<추적ID 또는 #이슈>)
```

- **type** (영어): `feat` 기능 | `fix` 버그 | `docs` 문서 | `refactor` 구조 개선(동작 불변) | `test` 테스트 | `chore` 설정·의존성·잡무
- **scope** (선택): `app` | `server` | `shared` — 모노레포 어느 영역인지. 루트/공통 작업이면 생략 가능
- **요약** (한국어): 50자 내외, 끝에 마침표 없이
- **추적 참조** (있으면): 스프린트 추적 ID(`F-05`)나 이슈 번호(`#12`)를 괄호로

### 예시

```
feat(app): 좋아요 버튼 롱프레스 애니메이션 (F-05, #12)
fix(server): 문제 세트 중복 생성 방지 (#26)
chore: 커밋·PR 컨벤션 스킬 추가
```

## 하지 말 것

- `main`에 직접 커밋 (반드시 브랜치 → PR)
- 여러 관심사를 한 커밋에 몰아넣기
- 영어 요약, 마침표로 끝나는 요약, "WIP" 같은 무의미한 메시지
- `git add .` 로 무관한 파일 쓸어담기
