# PR 컨벤션 (Thumbs Up)

## PR 생성 전 체크 (순서대로)

1. **브랜치 확인** — `main`이 아닌 작업 브랜치인지. 커밋들이 커밋 컨벤션(`/commit` 스킬)을 따르는지.
2. **관심사 확인** — 이 PR이 **하나의 관심사**만 담는지. 섞여 있으면 분리 제안.
3. **연결할 이슈 확인** — 브랜치명(`feat/12-...`)에서 이슈 번호 추출. 없으면 사용자에게 확인.
4. **push** — `git push -u origin <branch>`

## 제목 형식 (커밋과 동일)

```
<type>(<scope>): <요약> (#이슈)
```

예: `feat(app): 홈 투데이 학습 진입점 구현 (#2)`

## 본문 형식 (템플릿 그대로 채우기)

```markdown
## 무엇을 / 왜
<!-- 이 PR이 하는 일과 이유. 스프린트 추적 ID(F-xx 등)가 있으면 함께 -->

## 변경 사항
- 

## 관련 이슈
Closes #<이슈번호>

## 체크리스트
- [ ] 제목이 커밋 컨벤션(`<type>(<scope>): 요약`)을 따른다
- [ ] 로컬에서 동작 확인
- [ ] 하나의 관심사만 담았다
```

- `Closes #nn`은 필수 — 머지 시 이슈가 자동으로 닫힌다.
- 체크리스트는 실제로 확인한 항목만 체크. **확인 안 했으면 체크하지 말고 사용자에게 알린다.**

## 생성 커맨드

```bash
gh pr create --title "<제목>" --body "<본문>" --base main
```

## PR 생성 후

1. **이슈 상태 라벨 갱신** — 연결된 이슈를 리뷰 대기로:
   ```bash
   gh issue edit <이슈번호> --remove-label "status: in-progress" --remove-label "status: todo" --add-label "status: review"
   ```
2. PR URL을 사용자에게 보여준다.

## 머지 규칙

- **Squash merge** 사용 (히스토리 1커밋으로).
- 머지는 사람이 결정한다 — AI가 임의로 머지하지 않는다.
